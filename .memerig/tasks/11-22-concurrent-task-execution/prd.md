# MemeRig 多会话多任务执行

## Goal

基于仓库内任务协议，支持多个独立 Agent 会话并行执行不同任务，记录执行和验收证据，并明确共享队列与 Vercel Board 的接入边界。

## Requirements

- 同一项目允许多个独立会话同时执行不同任务。创建、切换、结束其中一个会话不得改变其他会话的当前任务。
- 同一个任务允许多次执行和审查，但同一时间最多一个拥有写入权的实现执行。审查可以引用同一次执行的结果。
- 并行修改代码时，每个实现执行拥有独立工作区。所有会话从同一个任务存储读取任务、状态和回执。
- 结构化记录执行身份、会话、结果、验证和产物。执行结束与验收通过分别记录，重跑保留旧结果。
- 正常结束时由运行器写回执。异常结束后可以确认中断并恢复，旧会话恢复运行后不得覆盖新结果。
- 兼容现有任务记录、任务命令及不需要 Agent 会话的日常使用。单机路径使用仓库内脚本，离线可用。
- 把 Vercel Board 定位为跨机器共享队列的候选适配器。仓库内任务仍是需求与验收的主记录。

## Acceptance Criteria

- [ ] 在同一仓库启动两个真实进程，分别执行 A 和 B。两者可同时运行，读取自己的上下文，停止 A 后 B 的会话和执行保持有效。
- [ ] 两个进程同时领取同一任务，仅一个取得实现权。回收后重领时，旧执行无法续租、写结果或推进任务。
- [ ] 两个关联 worktree 可以修改同一相对路径而互不覆盖，并且读取同一份任务记录。合并由独立审查处理。
- [ ] 模拟执行进程正常退出、被杀死及写回执途中崩溃。重复恢复得到同一个结果，任务停留在可接手或可审查的状态。
- [ ] 执行退出码为 0、PR 已创建或旧执行已通过审查，均不能替代对当前执行的验收。必跑验证缺少或为 `not_run` 时不能完成受管任务。
- [ ] 未迁移的任务继续可读、可用。关闭任务保持原目录，所有本地流程在无 Vercel 服务的环境下验证。

## 范围

本任务交付同机多会话执行、工作区隔离和可靠收尾。首版支持用户明确选择要执行的任务。跨机器领取、按依赖自动派工与第三方同步的部署取决于实际使用需求，接入条件记录在技术方案中。
