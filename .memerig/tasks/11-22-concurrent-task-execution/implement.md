# 实施计划

本任务当前处于规划阶段。评审后按以下顺序实施，各阶段使用临时仓库的真实进程和 worktree 验证行为。

## 1. 任务身份与受管执行协议

- [ ] 盘点 `task.py`、`task_protocol.py`、`active_task.py`、现有队列读接口、hook、CLI 模板和 TypeScript 读者。确认同机 worktree 访问唯一任务存储的入口及现有命令兼容边界。
- [ ] 实现运行与审查回执 Schema、领取/续租/回收，以及按 `runId` 和任务版本校验的写入层。用现有锁串行化短操作，不锁住执行进程。
- [ ] 双进程验收：A 和 B 可并发持有；A 的两个竞争者只有一个成功；过期后新持有者能接手，旧持有者的续租和结算被拒绝。覆盖已有任务的 `list`、`show`、`start` 和 `complete`。
- [ ] 并发控制验证完成前保留受管入口关闭，旧任务无需迁移。

## 2. 启动、代码隔离与结果回填

- [ ] 给受管执行接入独立 worktree、明确的 `taskId`/`runId`/会话身份，以及可观测子进程退出的启动器。为失去领取的运行停止其子进程，保留尚未确认的工作区改动。
- [ ] 让启动器续租并写回执，将成功运行交给审查，将失败和中断留在可接手状态。为分步写入实现确定性的中断恢复与幂等重放。
- [ ] 用两个真实 Agent 入口或受控子进程运行 A/B。两个 worktree 编辑同一相对路径后内容各自独立，任务写入都进入同一个 owner。结束 A 后检查 B 的会话绑定、工作区和领取。
- [ ] 分别在初始化、运行期间、回执落盘后、状态更新后终止进程，验证重新进入任务命令时的恢复；重放结果与第一次运行一致，并拒绝旧结果覆盖新结果。

## 3. 审查门禁与交付

- [ ] 将审查结果绑定待审 `runId` 和提交，验证必跑项与版本匹配，再用现有生命周期写入层完成。对受管任务覆盖从 `start`、`update`、`complete` 进入的旁路；旧任务保留已有行为。
- [ ] 同步自举脚本与发行模板，为新增结构补充 Python / TypeScript 合同样例。更新任务协议与工作流状态规范，包含跨 worktree 和运行退出的边界。
- [ ] 用 `python .memerig/scripts/task.py schema` 和 `python .memerig/scripts/task.py show <id> --json` 检查旧入口。实现时添加针对领取、结算恢复和隔离的定向回归测试，并在 Windows 与 POSIX 各运行一次。修改 Node 消费方时运行受影响的任务协议测试与 `pnpm typecheck`。
- [ ] 最终验收演示 A/B 同时运行、A 中断后可接手、B 退出后自动进入待审、审查通过后才关闭。回退前停止新领取，核对所有在途运行，保留存量回执。
