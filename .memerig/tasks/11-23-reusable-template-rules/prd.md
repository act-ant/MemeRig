# 通用默认规范与可选 Rules 模板

## Goal

为各项目提供可复用的通用规范：少量适合作为默认模板的基线，以及由项目主动选择的 optional Rules。

## 已确认

- 用户参考：https://x.com/murong97358/status/2124531122826854873 。
- 用户已批准实现“Rules 与 Spec 并列目录 + 手动采用”方案。
- 需要分别评估默认规范和可选规则，不直接将整份规则强制加入所有项目。
- 已通过浏览器读取 X 正文；原帖明确警告其兼容性策略只适合部分 side projects。原作者身份、token 消耗及事故叙述未独立核实。
- 用户选择方案 1：内容优先，默认基线 + 可选规则目录 + 明确采用方式，复用现有机制。
- 用户进一步明确：Rules 类似 Spec，只是一种声明范畴，不是独立运行时或规则管理功能。
- 用户要求明确的 Rules / Spec 目录划分，以及可选规则的具体落地方式。复用机制不代表混放内容。

## Requirements

- 调研现有模板、规范和分发机制，优先复用现有约定。
- 给出默认／可选／项目专属规则的准入边界和候选清单。
- 考虑规则冲突、上下文负担、多平台加载以及更新时保留用户修改。
- Rules 位于 `.memerig/rules/`，Spec 位于 `.memerig/spec/`；复用声明式 Markdown、索引和上下文机制，不增加独立规则引擎、启停状态或自动冲突解决器。
- Rule 描述可复用的约束、适用条件和判断依据；Spec 描述项目具体约定。目录区分不意味着新的优先级体系；冲突必须明确协调。
- 首批可选声明覆盖 clean-cutover、production-compatibility、dependency-governance、architecture-research；需明确来源目录、项目采用目录、索引引用、上下文加载、移除及升级方式。
- 保持 blank 初始化仅生成既有 Spec README、不填充项目约定；模板中未采用的参考规则不作为项目约束加载。

## Review Gate

- 用户已确认目录及采用方式，并明确授权开始实现。

## Acceptance Criteria

- [x] 现状判断提供仓库文件证据，见 research/rule-layering.md。
- [x] 明确默认与可选候选项及取舍依据；用户已选择内容优先范围。
- [x] 完善设计、实现步骤和验证方案，并获得实现批准。
- [x] 初始化和更新交付默认 Rules，保留项目 Spec 与本地规则修改。
- [x] 主会话和子代理能获得适用规则正文；未采用的目录内容不会加载。
- [x] 四个可选规则及中英文手动采用文档可用，并验证相关行为。

## Out of Scope

- 不添加 Rules 安装/启停命令或初始化选择 UI；不自动安装可选规则。
- 不整包照搬未经审阅的外部提示词，不覆盖用户现有工作。
- 不新增 Rules 管理命令、通用策略引擎或规则优先级体系；允许明确的内容目录与既有加载链路的必要适配，不将规则文档变成操作流程、Skill 或 Workflow。
