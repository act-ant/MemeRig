# Repository Package Map

These guidelines describe the current MemeRig repository shape and how package
keys in `.memerig/config.yaml` map to source code and specs.

## Purpose

Keep MemeRig package/spec routing aligned with the actual repository so
`get_context.py --mode packages`, task package binding, and future AI sessions
load the right guidance.

## Package Map

| Package key | Path | Package name | Spec path | Purpose |
| --- | --- | --- | --- | --- |
| `cli` | `packages/cli` | `memerig` | `.memerig/spec/cli/**` | User-facing CLI, templates, migrations, release scripts, and platform configurators. |
| `core` | `packages/core` | `memerig-core` | `.memerig/spec/core/**` | Reusable SDK/domain primitives for channel, mem, task, and testing APIs. |

## Workspace Layout

- `pnpm-workspace.yaml` declares `packages/*`, so the pnpm workspace packages
  are `packages/cli` and `packages/core`.
- The repository has no git submodules. `marketplace/` is vendored in-tree: it
  holds the spec, skill, and workflow templates served from
  `marketplace/index.json`, and tests diff its `workflows/native/workflow.md`
  against the bundled workflow template.
- `marketplace/` has no package manifest and no package-scoped specs. Do not
  add it to `.memerig/config.yaml` unless it gains package-level
  implementation ownership or specs.

## Contracts

- `.memerig/config.yaml` uses stable MemeRig package keys (`cli`, `core`)
  rather than npm package names. These keys are part of spec paths and task
  package bindings.
- `default_package` is `cli`; new tasks without `--package` bind to CLI because
  most MemeRig workflow/runtime changes are CLI-owned.
- Existing tasks keep their frozen `task.json.package`. Changing
  `.memerig/config.yaml` does not retroactively rebind old tasks.
- Package-context output is generated by
  `.memerig/scripts/common/packages_context.py`, which scans
  `.memerig/spec/<package>/<layer>/index.md` for each configured package.

## Checks

```bash
python3 ./.memerig/scripts/get_context.py --mode packages
git diff --check -- .memerig/config.yaml .memerig/spec
```
